## 4. 实验设计摘要

### 4.1 测试床

- Linux VM（UTM/Lima/云主机）+ 3 个 netns：`auth`（BIND/Knot + 实验区）、`res`（Unbound/BIND/PowerDNS Recursor）、`atk`（Scapy）、可选 `cli`（dig）。
- 地址：`192.0.2.0/24`、`2001:db8::/32`；无默认路由；IPv4/IPv6 egress DROP；实验后销毁。
- 抓包：res 侧 veth；抓包前关闭 GSO/GRO/TSO；确认 offset/MF 真实可见。

### 4.2 触发分片的不等式（先记这一条）

设响应 DNS 负载 `R`、客户端 EDNS 缓冲区 `E`、服务器最大 UDP 响应 `S`、路径 MTU `M`、IP+UDP 头开销 IPv4=28 / IPv6=48：

- `R > M − 28`（v4）/ `R > M − 48`（v6）且 `R ≤ min(E, S)` → UDP 分片（目标）；
- `R > min(E, S)` → TC → TCP（不是分片）；
- 矩阵同时测 `EDNS=1232` 与 `EDNS=1400`；服务器 `max-udp-size` 不能留默认值。

### 4.3 六个最小实验单元（3–5 人日）

| 单元 | 目的 | 关键配置 | 产出 |
|---|---|---|---|
| U1 | 基线大响应但不分片 | MTU 1500；EDNS 4096；R < M−28 | 尺寸分布、TC 比例 |
| U2 | IPv4 分片/重组 | auth veth MTU 700；R>M−28；R≤min(E,S) | 分片率、重组成功率、时延 |
| U3 | 第二片伪造注入 | on-path 读 IPID + 手工尾片；再试 off-path | 注入成功率 vs IPID 猜测次数 |
| U4 | 重叠/顺序策略差分 | 不同 OS/解析器 | 重组策略差异表 |
| U5 | 检测 TPR/FPR | Zeek/Suricata frag3/eBPF + 正常分片负样本 | TPR/FPR/吞吐 |
| U6 | 缓解消融 | EDNS 1232/1400、TC+TCP、R6 丢弃、PMTUD 加固 | 收益 vs 合法解析代价曲线 |

### 4.4 大响应区设计（最小版）

- 区：`lab.test.`；权威：BIND9 或 Knot；关闭 `minimal-responses`；`max-udp-size/udp-max-payload` 调到 4096。
- 记录：`big TXT "250B×10"`（一条 TXT 内多个 255B 字符串）或多条 TXT；DNSSEC（NSEC3/ECDSA）增强；可选 PQ 大签名。
- 验证：`dig @auth big.lab.test TXT +bufsize=4096 +ignore` 看 `MSG SIZE`；`+tcp` 对照。

### 4.5 安全伪造分片（骨架）

```python
# 仅隔离 netns；IPID 需与合法首片一致；第二片 offset = 首片 IP 负载长度 / 8
from scapy.all import IP, Raw
IPID, AUTH, RES = 0x1234, "192.0.2.10", "192.0.2.20"
L = 544  # 8 的倍数；首片 IP 负载长度
first  = IP(src=AUTH, dst=RES, id=IPID, flags="MF") / Raw(udp_payload[:L])
second = IP(src=AUTH, dst=RES, id=IPID, flags=0, frag=L // 8) / Raw(forged_tail)
# send(first); send(second)  # 仅在隔离实验网段
```

- 先抓真实合法首片，再用抓到的 IP 负载构造尾片，可避免偏移/UDP 长度错误。
- IPv6 需 `fragment6()`/手工 Fragment 头；Linux UDP 可能置 DF，需 `net.ipv4.ip_no_pmtu_disc=1` 或 socket `IP_MTU_DISCOVER=DONT`。
- 伪造 ICMP Frag Needed 是 RUC/FRAGJAM 的原语，仅在隔离环境对自己的 auth 使用。

## 7. 风险与缓解

| 风险 | 缓解 |
|---|---|
| PQ 方向被抢发（高） | W1 锁 delta；W1–W2 arXiv 占位；保留 IPv6/中间盒作第二卖点 |
| 与 POPS/RUC 撞车（中—高） | 只做防御侧未覆盖的增量；引言逐条对比 |
| 触发不了分片 | 按不等式 + DF 陷阱 + TC 窗口排查；先 U1/U2 |
| 实验室结果无法外推 | 多版本 + 双栈 + 中间盒；明确 limitation |
| 伦理/合规 | 隔离 + 文档地址 + 无真实目标；主动测量先获许可 |
| 工件不可复现 | CI + 干净环境复验 + 版本锁定 |

## 8. 伦理与披露 checklist

- [ ] 只用 RFC 5737 / RFC 3849 文档地址；无真实域名解析。
- [ ] 每个 netns 无默认路由；IPv4/IPv6 egress DROP；实验后销毁。
- [ ] 不针对任何真实解析器/权威服务器/第三方网络做分片注入或伪造 ICMP。
- [ ] 主动测量仅针对公开且条款允许的目标，或使用 RIPE Atlas/DITL/OpenINTEL。
- [ ] 发现真实漏洞：厂商/CERT/CNVD 协调披露（常见 90 天，以政策为准）；论文不公开完整攻击脚本与目标列表。
